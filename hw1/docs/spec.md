# Спецификация — ДЗ №1 «ВышКат»

## 1. Цель

Консольное приложение учёта парка кикшеринга «ВышКат». Оператор парка
принимает транспорт (после техосмотра) и ставит на баланс вещи, получает
отчёты: число единиц, суммарное суточное энергопотребление, список транспорта
для новичков и полный инвентарный список с номерами.

## 2. Область

**Входит:**

- приём транспорта: электросамокат, велосипед, электровелосипед;
- техосмотр транспорта перед приёмкой (принять / отклонить с причиной);
- постановка на баланс вещей: шлем, док-станция, зарядный шкаф;
- автоматическая выдача инвентарных номеров;
- отчёты: число единиц, суммарная энергия, транспорт для новичков, инвентарный список;
- валидация ввода и понятные сообщения об ошибках;
- демо-сценарий, который показывает все возможности приложения.

**Не входит:**

- хранение данных между запусками (парк живёт в памяти);
- удаление и списание техники;
- сотрудники, станции аренды, склад запчастей, сама аренда и оплата;
- GUI, сеть, аутентификация.

## 3. Предметная модель (кратко)

| Сущность         | Инв. номер | Энергия, кВт·ч/сут | Простота 1–10 | Транспорт | Техосмотр |
|------------------|:----------:|:------------------:|:-------------:|:---------:|:---------:|
| Электросамокат   | да         | да                 | да            | да        | да        |
| Велосипед        | да         | нет                | да            | да        | да        |
| Электровелосипед | да         | да                 | да            | да        | да        |
| Шлем             | да         | нет                | нет           | нет       | нет       |
| Док-станция      | да         | да                 | нет           | нет       | нет       |
| Зарядный шкаф    | да         | да                 | нет           | нет       | нет       |

Обоснование абстракций — в README и ADR.

## 4. Команды и сценарии

Приложение — REPL: строка = команда и аргументы через пробел. Название — одно
слово без пробелов (`Ninebot-Max`). Дробные числа — через точку (`0.4`).

| Команда | Описание | Пример ввода | Пример вывода |
|---------|----------|--------------|---------------|
| `add-vehicle <вид> <название> <простота> [кВт·ч]` | принять транспорт после техосмотра; вид: `scooter`, `bike`, `ebike`; кВт·ч — только для электрических | `add-vehicle scooter Ninebot-Max 7 0.4` | `Техосмотр пройден. Принят: Ninebot-Max, инв. № VK-SC-0001` |
| `add-item <вид> <название> [кВт·ч]` | поставить вещь на баланс; вид: `helmet`, `dock`, `cabinet`; кВт·ч — для `dock` и `cabinet` | `add-item helmet Шлем-M` | `На баланс поставлен: Шлем-M, инв. № VK-HL-0001` |
| `report` | число единиц (всего, транспорт, вещи) и суммарная энергия | `report` | `Всего: 5 (транспорт: 3, вещи: 2)`<br>`Суточное энергопотребление: 3.20 кВт·ч` |
| `beginners` | транспорт, который можно выдавать новичкам | `beginners` | `VK-BK-0001  Stels-Navigator  простота 9` |
| `inventory` | все объекты на балансе: инв. номер, вид, название | `inventory` | `VK-SC-0001  электросамокат  Ninebot-Max` |
| `demo` | заполнить парк тестовыми данными и выполнить все сценарии с выводом | `demo` | пошаговый вывод сценариев 1–7 |
| `help` | список команд | `help` | справка |
| `exit` | выход | `exit` | `Пока!` |

Ключевые сценарии:

1. Оператор принимает электросамокат с корректными данными → техосмотр
   пройден, выдан инвентарный номер.
2. Оператор принимает транспорт, который не проходит техосмотр → приём
   отклонён, причина выведена, парк не изменился.
3. Оператор ставит на баланс шлем и зарядный шкаф → выданы инвентарные номера,
   техосмотр не проводится.
4. `report` → число единиц и сумма суточного расхода только по потребителям
   энергии (велосипед и шлем в сумму не входят).
5. `beginners` → только транспорт с простотой ≥ 6; вещи в список не входят.
6. `inventory` → и транспорт, и вещи с номерами.
7. Некорректный ввод (неизвестный вид, простота 15, отрицательная энергия,
   нехватка аргументов) → ошибка «что произошло → что делать», состояние
   парка не изменилось, приложение продолжает работу.

## 5. Функциональные требования

- FR-1: Приложение принимает в парк транспорт трёх видов: электросамокат,
  велосипед, электровелосипед.
- FR-2: Перед приёмкой транспорт проходит техосмотр (`ServiceCenter`).
  Отклонённый транспорт в парк не попадает, оператор видит причину.
- FR-3: Правило техосмотра: транспорт отклоняется, если суточный расход
  энергии больше 2.0 кВт·ч (признак неисправной батареи). Правило задаётся
  реализацией `ServiceCenter` и заменяется без правки кода парка.
- FR-4: Приложение ставит на баланс вещи: шлем, док-станцию, зарядный шкаф.
  Вещи техосмотр не проходят.
- FR-5: Каждый объект на балансе получает уникальный инвентарный номер
  формата `VK-<код вида>-<NNNN>` (`SC` — электросамокат, `BK` — велосипед,
  `EB` — электровелосипед, `HL` — шлем, `DS` — док-станция, `CC` — зарядный
  шкаф). Нумерация — своя для каждого вида, с 0001.
- FR-6: Отчёт показывает число единиц (всего, транспорт, вещи) и суммарное
  суточное энергопотребление всех потребителей энергии на балансе.
- FR-7: Список для новичков содержит только транспорт с простотой ≥ 6.
  Правило отбора выделено отдельно и заменяется без правки кода парка.
- FR-8: Инвентарный список выводит номер, вид и название каждого объекта
  на балансе — и транспорта, и вещей — в порядке постановки на баланс.
- FR-9: Команда `demo` выполняет сценарии 1–7 из раздела 4 и печатает
  результат каждого шага.

## 6. Нефункциональные требования и ограничения

- Go 1.26.
- DI-контейнер — `go.uber.org/dig`. Зависимости регистрируются и собираются
  в контейнере в одной точке (`cmd/vyshkat`); пакеты предметной области
  и консоли о контейнере не знают и получают зависимости через конструкторы.
- Предметная область не выполняет ввод-вывод; консоль — отдельный пакет,
  работает через `io.Reader`/`io.Writer`.
- Простота — целое число от 1 до 10; суточный расход — число больше 0.
- Ошибки выводятся по схеме «что произошло → что делать», приложение после
  ошибки не завершается.
- Покрытие тестами — не ниже 60% (`make cover`).
