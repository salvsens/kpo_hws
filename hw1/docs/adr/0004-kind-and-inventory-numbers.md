# 0004. Вид объекта и выдача инвентарных номеров

Дата: 2026-10-25

## Статус

Принято. Закрывает открытый вопрос ADR-0001.

## Контекст

- Номер имеет формат `VK-<код вида>-<NNNN>`, нумерация своя для каждого
  вида (FR-5). Инвентарный список выводит вид объекта по-русски (FR-8).
  Значит, у каждого объекта должен быть вид: код и название.
- Конструкторы домена требуют номер сразу (ADR-0001), а техосмотр
  проверяет уже созданный объект (FR-2).
- Если выдавать номер до техосмотра и не возвращать его при отказе,
  в нумерации появятся дыры: `VK-SC-0001`, `VK-SC-0003`, а `0002` нет
  нигде на балансе.

## Решение

Вид объекта — значение в домене:

```go
type Kind struct {
    Code  string // префикс номера: "SC"
    Title string // название для вывода: "электросамокат"
}
```

- Шесть значений: `SC` электросамокат, `BK` велосипед, `EB`
  электровелосипед, `HL` шлем, `DS` док-станция, `CC` зарядный шкаф.
- Вид хранится в `baseAsset`; метод `Kind()` входит в интерфейс `Asset`.
  Каждый конструктор передаёт свой вид, поэтому вид нельзя перепутать
  или забыть.

Выдача номера — в два шага, в пакете `fleet`:

1. `NextID(kind)` возвращает следующий свободный номер вида и ничего
   не меняет: повторный вызов даёт тот же номер.
2. `AddVehicle` / `AddItem` при успешной постановке на баланс увеличивают
   счётчик вида (`map[domain.Kind]int`). При отказе техосмотра счётчик
   не меняется, следующий объект получит тот же номер.

`AddVehicle` / `AddItem` отклоняют объект, если `v.ID()` не равен
`NextID(v.Kind())`: так нельзя поставить на баланс объект с чужим или
повторным номером.

## Альтернативы

- Сопоставление «тип → вид» через `switch v.(type)` в `fleet` — отклонено:
  новый вид требует правки `fleet`, а забытый `case` компилятор не ловит
  (объект молча получит «неизвестный» вид). С `Kind()` в интерфейсе
  новый тип без вида не соберётся (OCP).
- Номер выдаётся сразу и сгорает при отказе — отклонено: дыры в нумерации
  мешают учёту.
- Парк сам создаёт объект через переданное замыкание
  `AddVehicle(kind, build func(id string) (domain.Vehicle, error))` —
  работает, но усложняет API ради того же результата.
- Объект создаётся без номера, номер присваивается после техосмотра —
  отклонено: объект на время был бы в некорректном состоянии,
  нарушается инвариант «номер не пустой» (ADR-0001).

## Последствия

- Плюсы: новый вид (моноколесо) — новое значение `Kind` и тип в домене,
  `fleet` и отчёты не меняются. Нумерация без дыр.
- Минусы/риски: русское название вида живёт в домене, хотя относится
  к выводу; приемлемо, пока интерфейс один (консоль). Вызывающий код
  делает два шага (`NextID`, затем `Add...`) вместо одного.
