# 0005. Техосмотр и правило «для новичков»

Дата: 2026-10-25

## Статус

Принято

## Контекст

- Техосмотр решает, принять транспорт или отклонить, и сообщает причину
  отказа (FR-2). Правило техосмотра заменяется без правки парка (FR-3),
  а в тестах техосмотр подменяется через DI (критерии приёмки).
- Правило «для новичков» (простота ≥ 6) тоже заменяется без правки
  парка (FR-7); ТЗ разрешает его усложнить.
- Отказ на техосмотре — нормальный результат проверки, а не сбой.

## Решение

Оба правила — интерфейсы в пакете `fleet`, объявленные на стороне
потребителя (ADR-0002). Парк получает их в конструкторе:
`fleet.New(sc ServiceCenter, policy BeginnerPolicy) *Fleet`.

Техосмотр:

```go
type Verdict struct {
    Accepted bool
    Reason   string // причина отказа; пусто, если принят
}

type ServiceCenter interface {
    Inspect(v domain.Vehicle) Verdict
}
```

- `Inspect` не возвращает `error`: проверка идёт в памяти, сбоя быть
  не может, а `error`, который всегда `nil`, — мёртвый код.
- Реализация по умолчанию отклоняет транспорт с суточным расходом больше
  2.0 кВт·ч (FR-3). Транспорт без потребления энергии (велосипед) по
  этому правилу проходит.
- Для парка отказ — ошибка операции: `AddVehicle` возвращает
  `ErrInspectionRejected`, обёрнутую через `%w` вместе с причиной.
  Консоль проверяет её через `errors.Is` и выводит причину.

Правило для новичков:

```go
type BeginnerPolicy interface {
    Allows(v domain.Vehicle) bool
}
```

- Реализация по умолчанию — `MinSimplicityPolicy{Min: 6}`.
- `Fleet.Beginners()` возвращает транспорт, который разрешает правило;
  вещи в список не входят (они не `Vehicle`).

`Fleet` возвращает данные, а не текст: `Report()` — структура
`Report{Total, Vehicles, Items int; DailyKWh float64}`, списки — срезы
интерфейсов `[]domain.Vehicle`, `[]domain.Asset`. Форматирование —
ответственность `cli` (SRP).

## Альтернативы

- `Inspect(v) error`, где отказ — ошибка: смешивает «проверка не прошла»
  и «проверку не удалось провести».
- `Inspect(v) (Verdict, error)`: `error` всегда `nil` (YAGNI). Если
  появится внешний техосмотр (сеть, БД), сигнатура расширится.
- Правило для новичков как функциональный тип
  `func(domain.Vehicle) bool`: короче, подменяется одной строкой, но при
  появлении состояния или второго метода (`Description()` для вывода)
  пришлось бы переделывать в интерфейс.
- Порог `>= 6` прямо в `Fleet` — отклонено: нарушает FR-7 и OCP.

## Последствия

- Плюсы: замена правила — новая реализация и одна строка в контейнере
  (ADR-0003); в тестах парк получает фейк, без контейнера.
- Минусы/риски: два интерфейса с одной реализацией в продакшн-коде;
  оправдано требованием подмены в тестах и FR-3/FR-7.
