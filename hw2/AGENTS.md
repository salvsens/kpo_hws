# AGENTS.md — правила проекта «ПОС»

Учебный консольный журнал оценок на Go 1.26. Рабочая папка проекта —
`hws/hw2`. Сценарии и критерии приёмки описаны в
[спецификации](docs/spec.md), архитектурные решения — в [ADR](docs/adr/).

## Роль агента

Студент пишет решение. Агент предлагает небольшие шаги, объясняет решения,
проверяет код и пишет реализацию по явной просьбе студента.

## Команды

Выполняйте команды проекта через `Makefile` из `hws/hw2`.

- `make help` показывает доступные команды.
- `make run` запускает REPL, `make build` собирает `bin/pos`.
- `make test`, `make test-race` и `make cover` запускают проверки тестами.
- `make fmt` форматирует код. `make lint` запускает golangci-lint v2,
  а `make lint-config` проверяет схему `.golangci.yml`.
- После изменений Go-кода выполняйте `make check`. Для новой регулярной
  команды добавьте цель в Makefile с записью для `make help`.

## Комментарии в Go

Пишите комментарии к функциям, методам, пакетам и константам на английском
по правилам Simplified Technical English. Применяйте те же правила к
остальным doc-комментариям.

- Используйте активный залог и короткие предложения. Пишите до 25 слов
  в описательном предложении и до 20 слов в инструкции.
- Используйте словарь ASD-STE100 и устоявшиеся технические термины.
  Сохраняйте один термин для одного понятия. В этом проекте
  `criterion` — критерий, `score` — выставленный балл,
  `result` — рассчитанный итог. Используйте американское правописание.
- Начинайте doc-комментарий экспортируемого идентификатора с его имени,
  а комментарий пакета — с `Package <name>`. Завершайте предложения точкой.
- Описывайте поведение, значимые условия и гарантии. Если функция
  возвращает ошибку при определённом условии, укажите это условие,
  когда оно важно для вызывающего кода.

Примеры комментариев пакета, функции и константы соответственно.

```text
// Package domain defines the rules for student scores.
// MaxScore returns the highest score for the criterion.
// MaxTotalWeight is the maximum total weight in percent.
```

При ревью сверяйте формулировки с [ASD-STE100, Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf).

## Порядок работы

1. Спецификация → ADR → код. Если меняется принятое решение, обновите ADR
   до реализации. Направление зависимостей и сборка через `dig` описаны
   в ADR-0002 и ADR-0003.
2. Записывайте вклад ИИ в `AI_USAGE.md` по ходу работы. Указывайте, что
   предложил агент и что студент принял или изменил.
3. Предлагайте английское сообщение коммита по Conventional Commits.
   Коммиты делает студент.
