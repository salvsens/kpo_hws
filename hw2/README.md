# «ПОС» — преподавательская оценка студентов

ДЗ №2 по КПО. Консольный журнал оценок одного курса на Go. Преподаватель добавляет студентов и критерии, выставляет и
исправляет оценки, рассчитывает взвешенный итог и выгружает его в CSV.

- [Спецификация и сценарии](docs/spec.md)
- [Архитектурные решения](docs/adr/)
- [Журнал использования ИИ](AI_USAGE.md)

## Запуск

Требуется Go 1.26.5 или новее. Для форматирования и проверки кода установите golangci-lint
v2. [Инструкция по установке](https://golangci-lint.run/docs/welcome/install/)

Из корня репозитория перейдите в `hw2`. Остальные команды выполняйте из этой папки.

```sh
cd hw2
make run         # запустить консоль
make check       # форматирование, vet, линтеры и тесты
make test-race   # тесты с детектором гонок
make cover       # тесты и отчёт о покрытии
make help        # все команды Makefile
```

Демо выполняет обычные команды на отдельном пустом журнале. Для каждого запуска используйте новый путь к файлу.

```sh
demo_dir=$(mktemp -d)
printf 'demo %s\nexit\n' "$demo_dir/итог ПОС.csv" | make run
cat "$demo_dir/итог ПОС.csv"
```

В демо итог сначала составляет `7.70`. Попытка заменить `8/10` на
`12/10` отклоняется. После исправления оценки за проект итог равен `9.20`. После отмены этой оценки текущий итог равен
`8.00`, а финальный недоступен. Демо вновь выставляет оценку за проект и сохраняет финальный итог.

```csv
student_id,student_name,mode,result
S-001,Анна Смирнова,final,9.20
```

## Команды консоли

| Команда                                        | Действие                                                   |
|------------------------------------------------|------------------------------------------------------------|
| `add-student <имя>`                            | Добавить студента и получить ID.                           |
| `students`                                     | Показать студентов в порядке добавления.                   |
| `add-criterion <максимум> <вес> <название>`    | Добавить критерий. Вес указывается целым числом процентов. |
| `criteria`                                     | Показать рубрикатор.                                       |
| `set-grade <студент> <критерий> <балл>`        | Выставить оценку по ID студента и критерия.                |
| `grades <студент>`                             | Показать выставленные оценки в порядке рубрикатора.        |
| `edit-grade <студент> <критерий> <балл>`       | Исправить выставленную оценку.                             |
| `cancel-grade <студент> <критерий>`            | Отменить выставленную оценку.                              |
| `result <студент> <current\|final>`            | Показать текущий или финальный итог.                       |
| `export <студент> <current\|final> <файл.csv>` | Записать выбранный итог в новый CSV.                       |
| `demo <файл.csv>`                              | Прогнать сквозной сценарий и сохранить итог.               |
| `help`, `exit`                                 | Показать справку или завершить сеанс.                      |

Баллы вводятся с точкой и точностью до двух знаков после неё. Имя студента, название критерия и путь к файлу могут
содержать пробелы. Журнал живёт в памяти до завершения процесса. CSV остаётся на диске и содержит итог одного студента
на момент выгрузки. При недоступном итоге файл не создаётся. Если путь занят, консоль предлагает выбрать другой.

## Структура

| Пакет                                       | Ответственность                                   |
|---------------------------------------------|---------------------------------------------------|
| [`cmd/pos`](cmd/pos/)                       | Сборка зависимостей через `dig` и запуск консоли. |
| [`internal/cli`](internal/cli/)             | Разбор команд, форматирование, ошибки и демо.     |
| [`internal/app`](internal/app/)             | Фасад сценариев, порты репозитория и экспорта.    |
| [`internal/domain`](internal/domain/)       | Агрегаты, инварианты и расчёт результата.         |
| [`internal/memory`](internal/memory/)       | Хранение студентов и рубрикатора в памяти.        |
| [`internal/csvexport`](internal/csvexport/) | Запись готового результата в CSV.                 |

В Ports and Adapters зависимости направлены внутрь.

```text
cli       → app, domain
memory    → app, domain
csvexport → app
app       → domain
```

`cli` вызывает `app.Gradebook` и использует доменные ошибки для подсказок.
`app` объявляет интерфейсы `Repository` и `ResultExporter`. Адаптеры реализуют эти интерфейсы. `cmd/pos` связывает
конкретные реализации через
`container.Provide` и запускает REPL через `container.Invoke`. Демо получает фабрику, которая создаёт пустой репозиторий
для каждого запуска.
[Архитектура](docs/adr/0002-ports-and-adapters.md) ·
[Сборка зависимостей](docs/adr/0003-di-uber-dig.md)

## Карта DDD и правила

| Термин     | Представление                            | Правило                                                                                     |
|------------|------------------------------------------|---------------------------------------------------------------------------------------------|
| Студент    | `Student`, сущность и корень агрегата    | Студенты различаются по ID. У студента максимум одна действующая оценка на критерий.        |
| Рубрикатор | `Rubric`, корень агрегата                | ID критериев уникальны внутри рубрикатора. Сумма весов не превышает 100%.                   |
| Критерий   | `Criterion`, сущность внутри рубрикатора | Оценка ссылается на критерий по ID. У критерия есть название, положительный максимум и вес. |
| Вес        | `Weight`, объект-значение                | Целое число от 1 до 100. Два веса по 40% равны.                                             |
| Оценка     | `Evaluation`, значение внутри студента   | Содержит ID критерия и балл от нуля до максимума включительно.                              |
| Итог       | `CalculateResult`, доменный сервис       | Пересчитывается по действующим оценкам и рубрикатору при каждом запросе.                    |

`Student` управляет выставлением, исправлением и отменой оценок. При исправлении фасад загружает снимки студента и
рубрикатора, вызывает доменную операцию и сохраняет обновлённого студента после успешной проверки. Репозиторий копирует
карту оценок и срез критериев при чтении и записи, чтобы изменения снимка не меняли сохранённый журнал.
[Модель и границы агрегатов](docs/adr/0001-student-and-rubric-aggregates.md)

### Как рассчитывается итог

Сервис суммирует вклады `балл / максимум × вес`, делит на сумму учтённых весов и умножает на 10. При `8/10` и `15/20` с
весами 40% и 60% это
`10 × (8/10 × 40 + 15/20 × 60) / 100 = 7.70`.

Текущий итог учитывает критерии с выставленной оценкой. Выставленный ноль входит в расчёт со своим весом. Финальный итог
доступен при сумме весов 100% и выставленной оценке по каждому критерию. Сервис считает на точных дробях `math/big.Rat`
и округляет один раз до сотых. Ровно половина сотой округляется вверх. `result` и `export` используют один расчёт.
[Правила расчёта](docs/adr/0004-result-strategy.md)

## Паттерны GoF

| Группа        | Паттерн   | Где применяется и какую задачу решает                                                                                                                               |
|---------------|-----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Порождающие   | Фабрика   | [`NewEvaluation`](internal/domain/evaluation.go) ищет критерий и проверяет диапазон при создании оценки. Выставление и исправление используют одну проверку.        |
| Структурные   | Фасад     | [`Gradebook`](internal/app/gradebook.go) даёт консоли целые операции. Например, исправление оценки включает загрузку, доменную проверку и сохранение за один вызов. |
| Поведенческие | Стратегия | [`CurrentResult` и `FinalResult`](internal/domain/result.go) решают, доступен ли итог и какие критерии учитывать. Формула и округление находятся в общем сервисе.   |
