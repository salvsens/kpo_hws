# Спецификация — ДЗ №2 «ПОС»

## 1. Цель

«ПОС» (Преподавательская оценка студентов) — консольное приложение для
ведения журнала одного курса. Преподаватель добавляет студентов и критерии
оценивания, выставляет, исправляет и отменяет оценки, рассчитывает
взвешенный итог студента и выгружает его в CSV.

## 2. Область

- Список студентов и единый рубрикатор курса. Преподаватель может добавить
  студента или критерий и просмотреть текущие списки.
- Журнал оценок. Преподаватель может выставить, просмотреть, исправить
  или отменить оценку по паре «студент — критерий».
- Расчёт взвешенного итога одного студента и экспорт результата в CSV.
- Консольная справка и сквозная демонстрация на учебных данных.

Журнал хранится в памяти. Каждый запуск начинается с пустых списков,
а выгрузки остаются в файловой системе после выхода.

## 3. Предметная модель

| Понятие | Смысл и правила |
|---------|----------------|
| Студент | Сущность с уникальным ID и именем. У тёзок разные ID. |
| Критерий | Элемент рубрикатора с ID, названием, положительным максимумом баллов и положительным весом. |
| Рубрикатор | Набор критериев одного курса. При вводе и исправлении оценки рубрикатор определяет допустимый максимум. |
| Оценка | Выставленный балл по одному критерию одного студента. Для каждой пары действует максимум одна оценка. Допустимый диапазон включает ноль и максимум критерия. |
| Вес | Объект-значение, который задаёт долю критерия в расчёте. Вес сравнивают по его величине. |
| Итог | Результат расчёта по рубрикатору и действующим оценкам студента. Доменный сервис вычисляет итог при запросе. |

Отмена убирает оценку из журнала. Выставленные ноль баллов входят в расчёт
с весом своего критерия. После отмены по этому критерию можно снова
выставить оценку.

### Правила расчёта

- Максимум критерия и выставленный балл могут быть целыми или дробными.
  Ввод с более чем двумя знаками после точки отклоняется.
- Вес критерия задаётся целым числом процентов от 1 до 100. При добавлении
  критерия сумма весов рубрикатора может вырасти максимум до 100%.
- Итог выражается по шкале от 0 до 10. Вклад критерия в числитель равен
  `балл / максимум × вес`. Сервис суммирует вклады, делит сумму на общий
  вес учтённых критериев и умножает на 10.
- Текущий итог (`current`) учитывает только критерии с выставленной
  оценкой. Если оценок пока нет, итог недоступен.
- Финальный итог (`final`) учитывает все критерии. Он доступен при сумме
  весов 100% и выставленной оценке по каждому критерию.
- Итог округляется один раз до сотых. При ровно половине сотой результат
  округляется вверх. Консоль и CSV показывают два знака после точки,
  например `7.70`.

## 4. Команды и сценарии

Приложение работает в REPL. Каждая команда вводится отдельной строкой.
Имя студента, название критерия и путь к CSV идут последним аргументом
своей команды и могут содержать пробелы. Десятичный разделитель — точка.

| Команда | Описание | Пример ввода | Пример вывода |
|---------|----------|--------------|---------------|
| `add-student <имя>` | Добавить студента и получить ID | `add-student Анна Смирнова` | `Студент добавлен (S-001): Анна Смирнова.` |
| `students` | Показать студентов | `students` | `S-001  Анна Смирнова` |
| `add-criterion <максимум> <вес> <название>` | Добавить критерий и получить ID | `add-criterion 10 40 Практика` | `Критерий добавлен (C-001): Практика, максимум 10, вес 40%.` |
| `criteria` | Показать рубрикатор с максимумом и весом каждого критерия | `criteria` | `C-001  Практика  максимум 10  вес 40%` |
| `set-grade <студент> <критерий> <балл>` | Выставить оценку | `set-grade S-001 C-001 8` | `Оценка выставлена (Практика): 8 из 10.` |
| `grades <студент>` | Показать выставленные оценки студента | `grades S-001` | `C-001  Практика  8 из 10  вес 40%` |
| `edit-grade <студент> <критерий> <балл>` | Исправить оценку | `edit-grade S-001 C-002 20` | `Оценка исправлена (Проект): 20 из 20.` |
| `cancel-grade <студент> <критерий>` | Отменить оценку | `cancel-grade S-001 C-002` | `Оценка отменена (Проект).` |
| `result <студент> <current\|final>` | Показать итог студента в выбранном режиме | `result S-001 final` | `Финальный итог (S-001): 7.70 из 10.` |
| `export <студент> <current\|final> <файл.csv>` | Сохранить выбранный итог в CSV | `export S-001 final result.csv` | `Итог сохранён в result.csv.` |
| `demo <файл.csv>` | Показать сквозной сценарий и выгрузить его итог | `demo demo.csv` | Результаты шагов ниже и путь к файлу. |
| `help` | Показать список команд | `help` | Список команд и их аргументов. |
| `exit` | Завершить работу | `exit` | `Работа завершена.` |

Аргументы `<студент>` и `<критерий>` принимают ID из списков. ID
выдаются последовательно с префиксами `S-` и `C-`, начиная с `S-001`
и `C-001` в каждом журнале. Конец входного потока завершает REPL.

### Сквозной сценарий

1. Добавить Анну Смирнову, практику с максимумом 10 и весом 40%, проект
   с максимумом 20 и весом 60%. Проверить списки студентов и критериев.
2. Выставить за практику 8 из 10, за проект 15 из 20. Команда `grades`
   показывает обе оценки, `result S-001 final` показывает `7.70`.
3. Попытаться изменить балл за практику на 12. Консоль сообщает
   `Балл 12 превышает максимум критерия «Практика». Введите балл от 0 до 10.`
   В списке остаётся 8 из 10, финальный итог по-прежнему `7.70`.
4. Исправить балл за проект на 20. Финальный итог становится `9.20`.
5. Отменить оценку за проект. `result S-001 current` показывает `8.00`.
   `result S-001 final` предлагает выставить оценку по критерию «Проект».
6. Заново выставить за проект 20 из 20, сохранить финальный итог
   командой `export S-001 final result.csv` и проверить файл.

На шаге 6 файл содержит заголовок и одну строку данных.

```csv
student_id,student_name,mode,result
S-001,Анна Смирнова,final,9.20
```

## 5. Функциональные требования

- **FR-1.** Добавить студента с непустым именем, получить его уникальный ID
  и просмотреть список студентов с ID и именами в порядке добавления.
- **FR-2.** Добавить критерий с непустым названием, максимумом и весом,
  получить его ID и просмотреть рубрикатор в порядке добавления.
- **FR-3.** Выставить оценку по ID студента и критерия. Для операции нужны
  существующие студент и критерий. Балл должен входить в диапазон от нуля
  до максимума критерия включительно. При повторном выставлении консоль
  предлагает команду исправления.
- **FR-4.** Показать оценки выбранного студента в порядке критериев
  рубрикатора. Для каждой выставленной оценки показать ID и название
  критерия, балл, максимум и вес.
- **FR-5.** Исправить или отменить существующую оценку. При исправлении
  действуют те же проверки балла, что и при выставлении. При отказе
  сохраняется прежняя оценка.
- **FR-6.** Рассчитать взвешенный итог по текущему состоянию рубрикатора
  и оценок. После исправления и отмены следующий запрос учитывает изменения.
- **FR-7.** Выгрузить рассчитанный итог одного студента в CSV в кодировке
  UTF-8 с заголовком из раздела 4 и одной строкой данных. Путь задаёт
  преподаватель. При недоступном итоге приложение сообщает причину
  до создания файла. Если файл уже существует, приложение предлагает
  выбрать новый путь.
- **FR-8.** Вывести справку по командам и выполнить сквозное демо
  от создания студента до выгрузки итога. Демо выполняет те же сценарии
  приложения на собственном пустом журнале.
- **FR-9.** Для неизвестной команды, неверного аргумента, пустого списка,
  неизвестного ID или ошибки записи показать понятное сообщение. После
  ошибки ввода или операции преподаватель может ввести следующую команду.

## 6. Нефункциональные требования и ограничения

- Go 1.26. Сборка, запуск и проверки выполняются через `Makefile`.
- Архитектура Ports and Adapters. Предметная область содержит инварианты
  и правила расчёта. Сценарии обращаются к хранилищу через порт репозитория.
  Консоль, хранение в памяти и запись CSV реализуются в адаптерах.
  Зависимости направлены от адаптеров к приложению и предметной области.
- DI-контейнер `go.uber.org/dig` собирает зависимости в точке входа
  `cmd/pos`. Сценарии получают зависимости через конструкторы.
- Фабрика создаёт проверенную оценку, фасад предоставляет сценарии
  консоли, стратегия задаёт правило расчёта в доменном сервисе.
- Комментарии к функциям, пакетам и константам пишутся на английском
  по правилам Simplified Technical English (ASD-STE100). Doc-комментарий
  к экспортируемому идентификатору начинается с его имени.
- README объясняет модель DDD, направление зависимостей, назначение
  каждого паттерна и вклад ИИ. Использование ИИ фиксируется в `AI_USAGE.md`.

## 7. Критерии приёмки

- [ ] `make check` проходит, `make run` запускает приложение.
- [ ] Консоль выполняет все команды и сквозной сценарий из раздела 4.
- [ ] Тесты модели покрывают ноль, максимум, выход за обе границы
      диапазона и неизвестный критерий.
- [ ] Некорректное исправление сохраняет исходную оценку.
- [ ] Тесты расчёта проверяют разные максимумы и веса, пропущенный
      критерий, округление и перерасчёт после исправления и отмены.
- [ ] Сумма весов свыше 100% отклоняется. При сумме ниже 100% финальный
      итог недоступен.
- [ ] Выгруженный CSV открывается и содержит тот же итог, что и консоль.
- [ ] README объясняет модель, архитектуру, паттерны и вклад ИИ.
- [ ] На защите можно показать проверку инвариантов и объяснить, где
      меняется правило расчёта.
