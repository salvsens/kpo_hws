# 0002. Структура пакетов Ports and Adapters

Дата — 2026-11-21

## Статус

Принято

## Контекст

Консоль должна выполнять сценарии журнала, который хранится в памяти,
и выгружать итог в CSV. Домен отвечает за правила оценивания. Вызовы
сценариев, доступ к хранилищу и файловый ввод-вывод требуют явных
границ. См. [спецификацию](../spec.md), FR-1–FR-9 и раздел 6.

## Решение

| Пакет | Ответственность |
|-------|-----------------|
| `internal/domain` | Агрегаты, инварианты, фабрика оценки, доменный сервис расчёта. |
| `internal/app` | Сценарии, фасад и порты репозитория и экспорта. |
| `internal/cli` | REPL, разбор команд, справка, сообщения об ошибках и демо. |
| `internal/memory` | Репозиторий, который хранит студентов с оценками и рубрикатор в памяти. |
| `internal/csvexport` | Запись рассчитанного результата в CSV. |
| `cmd/pos` | Сборка графа зависимостей и запуск REPL. |

Стрелки показывают направление зависимостей. Точка входа связывает
адаптеры с портами приложения. Адаптер репозитория использует типы
агрегатов из `domain`.

```text
cli ────────────→ app ──→ domain
memory ─────────→ app, domain
csvexport ──────→ app
```

- Фасад `app` предоставляет консоли операции уровня сценария. При
  исправлении оценки один вызов загружает данные, вызывает доменную
  операцию и сохраняет результат. Консоль разбирает аргументы и
  форматирует ответ.
- Порт репозитория объявляет `app`. Он работает с агрегатами из
  [ADR-0001](0001-student-and-rubric-aggregates.md). Адаптер в памяти
  возвращает независимые снимки изменяемых данных и принимает их
  при сохранении. Списки сохраняют порядок добавления.
- Сценарии показа и экспорта используют один расчёт итога. При экспорте
  приложение сначала получает итог, затем передаёт его с путём в порт
  экспорта. CSV-адаптер создаёт файл только по свободному пути.
- REPL получает потоки через `io.Reader` и `io.Writer`. Демо выполняет
  те же команды на новом экземпляре приложения с пустым репозиторием.

## Альтернативы

- Консоль напрямую управляет хранилищем и доменными объектами. Для
  исправления и экспорта пришлось бы повторять порядок операций в
  обработчиках консоли и в других точках входа.
- Отдельные слои и интерфейсы для каждого сценария и типа данных.
  Текущие сценарии используют один журнал и один формат экспорта.
  Дополнительное дробление усложнило бы сборку и навигацию по коду.

## Последствия

- Сценарии можно проверить с репозиторием в памяти и подменой экспорта.
  Формат CSV и сообщения REPL проверяются в тестах адаптеров.
- Передача данных через порты требует явных контрактов. Снимки
  добавляют копирование при загрузке и сохранении изменяемых агрегатов.
