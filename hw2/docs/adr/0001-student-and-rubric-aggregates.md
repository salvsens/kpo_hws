# 0001. Агрегаты студента и рубрикатора

Дата — 2026-11-21

## Статус

Принято

## Контекст

Оценка относится к одному студенту и одному критерию. Для каждой пары
действует максимум одна оценка. При выставлении и исправлении нужно
найти критерий и проверить балл по его максимуму. При отказе журнал
сохраняет прежнюю оценку. См. [спецификацию](../spec.md), раздел 3
и FR-1–FR-5.

## Решение

| Понятие | Роль в модели |
|---------|---------------|
| `Student` | Корень агрегата и сущность с ID. Хранит действующие оценки студента по ID критерия. Два студента с одинаковым именем имеют разные ID. |
| `Rubric` | Корень агрегата курса. Хранит критерии и контролирует уникальность их ID и сумму весов до 100%. |
| `Criterion` | Сущность внутри рубрикатора. Её ID связывает критерий с оценками. При добавлении проверяются название и положительный максимум. |
| `Weight` | Объект-значение. Целый процент от 1 до 100. Два веса с одинаковой величиной равны. |
| `Evaluation` | Значение с ID критерия и выставленным баллом. Принадлежность студенту задаётся агрегатом. Исправление заменяет значение в той же паре. |

- Право изменить оценки принадлежит `Student`. Выставление требует
  свободной пары, исправление и отмена требуют существующей оценки.
  Чтение возвращает данные без доступа к изменяемой коллекции агрегата.
- Фабрика оценки в пакете `domain` используется и при выставлении,
  и при исправлении. Она находит критерий в переданном рубрикаторе
  и принимает балл от 0 до максимума включительно. Студент записывает
  новую оценку после всех проверок.
- Сценарий приложения загружает студента и текущий рубрикатор. При
  выставлении или исправлении рубрикатор служит источником правил.
  После успеха репозиторий сохраняет только студента с его оценками.
- Добавление критерия меняет только рубрикатор. ID, максимум и вес
  добавленного критерия действуют до конца сеанса, поэтому добавление
  нового критерия сохраняет корректность существующих оценок.

## Альтернативы

- Один агрегат на весь журнал. Он позволил бы проверять все ссылки
  внутри одной границы, но тогда для исправления одной оценки пришлось
  бы загружать и сохранять журнал целиком.
- Независимая запись на каждую оценку. Такой подход упрощает обращение
  к одной записи, но переносит контроль повторного выставления на
  границу хранилища и размывает ответственность за оценки студента.

## Последствия

- Правила изменения оценок тестируются на одном студенте и небольшом
  рубрикаторе. Фабрика обеспечивает общий порядок проверок для обеих
  операций записи.
- Если появится редактирование максимумов или удаление критериев,
  потребуется отдельное правило для ранее выставленных оценок. Сейчас
  согласованность двух агрегатов опирается на стабильность критериев.
